**Contract rules:** Workspace identity comes from verified JWT context. Customer mutations require workspace-owner; catalog admin mutations require platform admin, reason, and idempotency/correlation. `GET /me` includes exact Plan/Package, access/usage periods, limits/usage, auto-renew, grace, scheduled change, and retirement. Customer catalog exposes active published offers only. No free-resubscribe or immediate-cancel endpoint; `POST /renew` is the only customer renewal action. Limit fields in envelopes/DTOs use `-1` unlimited / `0` blocked / `>0` cap and carry `unlimited: true` when `-1` *(change-080)*.

**Stable catalog conflict codes** *(change-077)*: `SUBSCRIPTION_PACKAGE_IMMUTABLE` · `SUBSCRIPTION_PLAN_IMMUTABLE` · `SUBSCRIPTION_PACKAGE_ARCHIVED` · `SUBSCRIPTION_DEFAULT_FREE_REQUIRED` · `SUBSCRIPTION_DEFAULT_FREE_MUST_BE_FREE` · `SUBSCRIPTION_DEFAULT_FREE_INTERVAL_INVALID` · `SUBSCRIPTION_PLAN_RETIREMENT_REQUIRED` · `SUBSCRIPTION_RETIREMENT_NOTICE_TOO_SHORT` · `SUBSCRIPTION_FREE_PRICE_INVALID` · `SUBSCRIPTION_PAID_PRICE_INVALID` · `SUBSCRIPTION_PLAN_PRICE_PRECISION` · `SUBSCRIPTION_BILLING_INTERVAL_INVALID` · `SUBSCRIPTION_QUOTA_INTERVAL_INVALID` · `SUBSCRIPTION_PACKAGE_LIMIT_INVALID` · **new**: `SUBSCRIPTION_PACKAGE_NAME_TAKEN` · `SUBSCRIPTION_PACKAGE_TIER_TAKEN` · `SUBSCRIPTION_PLAN_DISPLAY_NAME_TAKEN` · `SUBSCRIPTION_DEFAULT_FREE_NOT_LIVE` · `SUBSCRIPTION_DEFAULT_FREE_RETIRING`. **Lifecycle/quota codes** *(change-080)*: `SUBSCRIPTION_RENEW_WINDOW_CLOSED` · `SUBSCRIPTION_ADMIN_LOCKED` · `SUBSCRIPTION_USAGE_PERIOD_MISSING` · `PAYMENT_IDEMPOTENCY_KEY_REUSED`. Every code is rendered as a localized message by both frontends.

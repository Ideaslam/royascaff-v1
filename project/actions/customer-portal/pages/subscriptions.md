## Module: Subscriptions

### Subscriptions & Billing Page
- Route: `/app/subscriptions`
- Components: current Plan+Package version card; separate billing/access and quota-window dates; Package cadence and atomic usage bars; auto-renew; scheduled downgrade/replacement banner; persistent retiring-Plan banner with deadline and replacement CTA; bilingual/RTL active-published Plan cards populated with Package benefits; server preview dialog; immutable invoice history; Pay Now (hidden for invoices past `expiresAt`); payment-result toast; **Renew / Pay now** CTA in the PAST_DUE banner and near period end, with an "Ask the workspace owner to renew" message for non-owners; "Renewal processing" banner when the period has ended but the job has not yet rolled it *(change-080)*.
- Service: `getPlans` → `GET /subscriptions/plans`; `getMySubscription` → `GET /subscriptions/me`; `previewChange` → `POST /subscriptions/change/preview`; `upgrade` → `POST /subscriptions/upgrade`; `scheduleDowngrade` → `POST /subscriptions/downgrade`; `cancelDowngrade` → `DELETE /subscriptions/downgrade`; `setAutoRenew` → `PATCH /subscriptions/auto-renew`; `getInvoices` → `GET /subscriptions/me/invoices`; `payInvoice` → `POST /subscriptions/invoices/:invoiceId/pay`; `renew` → `POST /subscriptions/renew` *(change-080)*.
- Guard: authGuard + onboardingGuard; mutation controls visible only to workspace owner, with backend authorization authoritative.
- States: loading, empty replacement catalog, immutable current version, retirement scheduled/cancelled, notification delivery delayed, replacement pending/failed/paid, grace, scheduled change, renewal processing, renew window closed (`SUBSCRIPTION_RENEW_WINDOW_CLOSED` → Upgrade), and action error/success.
- Notes: no Subscribe Free or destructive cancel. Plan and Package labels resolve in one fixed order *(change-077)* — `plan.displayName` → `plan.name` → `package.name`, using the `*Ar` variant when the active locale is Arabic and its value is non-empty; snapshot readers fall back to `snapshot.name`. Two Plans sharing a Package can therefore render distinct names, and Plans with empty `display*` render exactly as they do today. Usage reset label comes from Package cadence, not Plan billing interval. Upgrade preserves quota; downgrade/same-tier replacement applies at billing end and remains cancellable. Retirement warning remains visible from Plan state even if email fails. Never render provider tokens/raw gateway data. Usage bars render `unlimited: true` limits as Unlimited *(change-080)*. `SUBSCRIPTION_LOCKED` / `SUBSCRIPTION_ADMIN_LOCKED` errors (CSV connect and the global HTTP interceptor) render as translated EN/AR messages with a link to `/subscriptions` *(change-080)*. Retirement banner links to the successor Plan *(change-080)*.
